# 1.13.0 Android 模拟器验收

测试日期：2026-10-23。沿用本机两个隔离 AVD：Android 14 / API 34（720×1280）、Android 16 / API 36（720×1600），均为 x86_64、320 dpi，使用 host 图形后端。没有连接实体手机，也没有调用真实外部模型。

## 触摸、导航与牌桌

两个系统各完成 468 项检查，0 项失败。模型选择使用实际 Android 输入事件执行向上滑、向下滑、搜索后点选，以及连续两次分层返回。列表拖动不会误选，外层设置保持原位置；首次返回关闭模型选择，第二次返回设置分类。

Android 16 验收实际暴露同一次 BACK 按键产生两次系统返回通知，间隔可达 174 毫秒，且按键与通知顺序不固定。现按 350 毫秒窗口合并重复返回通知，独立单元测试覆盖延迟重复与下一次正常返回；两个系统重新验收通过。

2～9 人逐桌完成翻前至摊牌、合法动作与筹码守恒检查；继续验证历史回放、训练、设置及混模型同桌。每台设备保存 17 张游戏视口截图，涵盖模型列表、六 / 九人座位气泡、API 请求列表、当前手内容锁定等；另保存原生返回后的全屏截图。

## 网络与凭据

通过 Android 网络栈连接电脑上的模拟 HTTP 服务，交替使用两个模型与独立模拟密钥。模拟单次生成达到长度上限，再验证自动提高额度重试成功；检查请求详情、用量、当前手保密和公开发言。模拟结果不代表真实提供商的质量、费用或牌力。

原生 Keystore 验证加密保存、端点绑定、强制停止重启读取、外部篡改密文拒绝、关闭记住后删除。由 ADB 额外检查不备份目录中的密文及删除结果，测试完成不遗留模拟密钥。

## 发布包与覆盖安装

测试应用使用独立包名 `com.somnicard.audit`；发布应用是 `com.somnicard.practice`。逐一核对全部 62 个游戏脚本的源文件摘要，并核对两个 APK 中全部 62 个编译游戏脚本字节一致。测试入口、测试脚本、模拟密钥及记录均不进入发布 APK。

两台模拟器均从已安装的 1.12.0 覆盖更新到 1.13.0。更新前后逐文件核对原有存档摘要不变；正式包启动后检查主页截图与日志，无脚本异常或 Java 崩溃。沿用同一签名证书，验证 v2 签名、ZIP / ELF 16 KB 对齐、ZIP CRC、网络权限、竖屏及禁止系统备份设置。

桌面 21 套回归和启动检查通过，合计 171,384 项断言；其中本版专项 864 项、AI 接口专项 330 项。包含固定种子 2,795 手、12,537 次动作和 1,530 次中途恢复。最终返回防抖改动后重跑本版与导航专项，并重跑两台原生验收。

本地 HTTP 模拟服务覆盖 429 错误展示、一次重试对应一次新请求、本手本地接管；还覆盖等待回复时暂停、取消后的迟到回复不执行、继续后的新回复只执行一次对手动作。翻前最后一次动作同时产生发翻牌事件，断言按玩家动作计数，避免将正常发牌误判为重复执行。

准备牌局、长列表和历史记录由测试脚本完成；点击、滑动、返回和输入文字由 Android 原生输入执行。目标控件坐标在布局稳定后读取，测试包使用独立包名 `com.somnicard.audit`。本次最终测试 APK 与正式 1.13.0 APK 的 62 个编译游戏脚本逐字节一致，正式 APK 未修改、未重新发布。

## 追加用户操作测试：发现的兼容性问题

2026-10-23 追加前后台压力测试，正式 1.13.0 APK 在两个 AVD 上均出现过连续 HOME / 返回后全黑。原有 `session.json` 保留且字节摘要不变，没有脚本异常或 Java 崩溃，但这不代表画面恢复通过。该问题目前仍未解决，不应把本页前面的功能通过结果理解为整包无已知问题。

Android 16 的现场日志包含 `EGL_BAD_SURFACE`；原生线程栈停在 `GLSurfaceView.GLThread.guardedRun`，调试读取到 `mSurfaceIsBad=true`、`mPaused=false`、`mHasSurface=true`。这将调查范围缩小到渲染表面恢复，但不足以证明实体手机也受影响，或确定是游戏、引擎还是模拟器驱动的责任。

随后对照实验中，关闭 Android frame pacing 的隔离临时包连续 10 次恢复正常，而未修改的正式包随后连续 10 次也恢复正常。因此没有把该配置试验合并为修复，也没有为此发布新 APK。正式包又通过一轮 10 次恢复检查，存档摘要仍相同；间歇性黑屏依然保留为未关闭缺陷。

证据位于 `.local/android-interactions/api34/production-background-cycle-3.png`、`api36/production-background-cycle-3.png`、`api36/production-black-stack.txt`、`api36/repro-log.txt` 及 `production-background.json`。后续正常恢复的记录不能覆盖先前黑屏证据。可在已启动并进入目标页面的自有测试 AVD 上运行 `python tools/run-android-background.py emulator-5554 5038` 复测；它只检查截图中是否有内容、保存日志和存档摘要，不清空正式游戏，也不证明所有控件都响应。
