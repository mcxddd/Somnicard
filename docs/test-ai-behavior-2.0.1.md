## 确认的问题与修复

1. **DeepSeek 输出额度被推理耗尽。** 原始九人桌转牌一次请求返回 `finish_reason=length`，`output_tokens=4096`、`reasoning_tokens=4096`、可见回复为空。扩大额度重试后成功，整个决策耗时约 49.38 秒；之后另一请求发生 60 秒超时。代码此前仅为 DeepSeek 直连设置结构化输出与关闭推理，漏掉 CommandCode 的 `deepseek/deepseek-v4...` 模型。现将该模型族应用相同默认设置，并保留服务明确拒绝参数时的有界兼容重试。此项是实时响应稳定性适配，不是牌力提升证明。
2. **行动历史缺少事实。** 原提示省略盲注实际金额、全押/完整加注标记、退回未跟注筹码及换街记录。已补充这些公开事实和位置，并限制换街牌面只能是当前公共牌的前缀。决策另提供当前成牌、实际跟注成本及能争夺的底池，避免重复算错；该信息不是胜率或策略指令，不提供其他人的底牌。
3. **旧对白可能错配新动作。** 原控制器只判断是否同一手、同一街；一个玩家在同一街再次行动后，先前请求的对白仍可能显示。自动化测试以六人翻前加注→被再加注→跟注、仍未结束翻前的局面复现。现拒绝该旧回复，并让已显示的气泡在本人再次行动或换街后消失；对白记录仍可查看。
4. **错误信息缺少诊断依据。** 连接错误现在附带引擎 transport result 和 HTTP 状态到脱敏诊断记录。原样本里的超时/连接失败不足以断言是模型服务、网络路径或设备中的哪一方造成，未宣称全部网络问题已修复。
5. **记忆统计含义不明确。** 提示明确 `hero_raises` 是任意街曾加注的手数，而不是翻前加注率。没有改变原存档结构。

DeepSeek 的[官方推理模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)说明了推理开关及默认开启行为；CommandCode 的[Provider API 文档](https://commandcode.ai/docs/provider)提供兼容端点。第三方网关是否接受特定参数仍以实际返回为准，因此保留兼容降级。

- 23 套全游戏自动测试及启动检查通过，覆盖多人规则、复盘、训练、导航、对白、存档与压力测试。
- 最后服务参数变更后，AI 网络回归 331 项、行为专项 21 项再次通过。模拟接口确认实际请求包含预期参数，拒绝参数时最多四次请求后停止或成功。
- **DeepSeek 最后一项参数适配是在其 50 次额度用完后完成，仅做了模拟接口验证，没有追加真实调用。** 事实/对白修复后的 20 次实测仍使用旧的 DeepSeek 生成参数。不能把其改善归因于最后的参数变更。
- GPT-6 Luna 的新增 50 次运行于当前修复代码，未发现新的格式、合法性、截断或网络错误。有限样本不能保证今后不发生。
- 两轮对局均固定在线“标准＋均衡”，其余座位为固定种子的本地标准对手。模型未设置可复现随机种子，两模型的动作会导致后续局面不同，故不是严格配对牌力实验。
- 没有跨三档强度排序、真人段位、长期盈利率或完整多人 GTO 认证；没有实体手机联网质量验收。
